# 가사 배치 개선 분석 및 구현 기록

상태: **IMPLEMENTED — 일반 곡의 구간 기반 배치, 최종 기호 검증, 초안 교정과 품질 분류를 구현했다.** 갱신일: 2026-11-15. 자동 검사와 실제 가창 확인은 구분하며 전체 가창 대응은 NOT_VERIFIED다.

이 문서는 Run Boy Run의 자동 결과에서 연장음이어야 할 자리에 원본 `la`가 남은 문제를 분석하고, 음표를 유지하면서 가사 배치를 개선할 기준을 정한다. 현재 사용법은 [README](../README.md#gradio-gui-실행), 기존 기능·검증 이력은 [GUI 구현 기록](gradio-gui-implementation.md), 기준은 [AGENTS.md](../AGENTS.md)와 [프로젝트 스킬](../.agents/skills/svp-vocal-alignment/SKILL.md)을 따른다.

1–4절은 개선 전 자동 결과·분석·실험 이력이다. 해당 수치를 새 알고리즘의 결과로 사용하지 않는다. 5–8절은 현재 구현 계약과 검증을 기록한다. 이전 154개 테스트 통과는 당시 구현 이력이며 새 개선이나 실제 가창 정확도의 근거가 아니다.

## 1. 목표와 보존 계약

- GUI의 수정 범위는 선택한 기존 음표의 `lyrics`뿐이다. `onset`, `duration`, `pitch`, `detune`, 음표 ID·개수·배열 순서, 그룹·트랙·템포·박자·오디오 참조와 나머지 필드는 모두 보존한다.
- TXT의 원문 단어, 순서와 반복 발생을 토큰 인덱스·행·열로 추적한다. 음절을 나눠 표현해도 어느 원문 토큰에서 왔는지 잃지 않는다.
- 원본과 기존 결과는 덮어쓰지 않는다. 새 GUI 결과의 `_LYRICS_FILLED.svp` 이름·게시 경계와 원본 오디오 경로 보존 계약을 유지한다.
- 모델 관측은 가사 대응의 근거이며 음표 이동 명령이 아니다. 모델 구간에 맞추려고 음표를 추가·삭제·분할·합치거나 시간·음높이를 변경하지 않는다.
- 업로드, 모델 선택, worker·GPU·취소 수명과 기존 Counting Stars 타이밍 CLI의 API·결과·실패 계약을 보존한다. Counting Stars 기존 자료를 사용하는 GUI 어댑터의 가사 전용·품질 표현 호환성은 별도로 확인한다.

## 3. 개선 전 코드에서 확인한 원인

### 3.1 일대일 배치 뒤에 지속음을 붙이는 순서

[general_matching.py](../svp_alignment/alignment/general_matching.py)의 `_monotonic`은 추정 음절과 음표의 일대일 연결, 음표 건너뛰기, 음절 건너뛰기를 비교한다. `match_words_to_notes`는 일부 음절이 미배치된 단어의 배치를 전부 제거한 뒤, 남은 음표에 지속음 후보를 붙인다.

현재 `-`는 앞서 배치한 마지막 음절과 다음 음표의 겹침이 음표 길이의 70% 이상이고, 음표 시작이 음절 시작 이상이며, 음표 종료가 음절 종료 +0.08초 이하일 때만 생성한다. 이 조건에 들지 않은 미배치 음표는 UNKNOWN 사유를 남기고 원래 가사를 보존한다. [general_pipeline.py](../svp_alignment/general_pipeline.py)의 `prepare_song`은 `lyric_fields`에 있는 음표만 갱신하므로 원본 `la`가 결과에 남는다. 모델이 `la`를 새로 생성한 것이 아니다.

사용자가 `la → -`로 고친 29곳 모두 70% 겹침 조건을 통과하지 못했다. 그중 28곳은 종료 +0.08초 조건도 통과하지 못했다. 예를 들어 자동본 33번 음표는 28.340–28.620초인데, 앞 `run`의 후보 음절 구간은 28.0125–28.4725초다. 겹침은 약 47.32%라 지속음으로 연결되지 않았다. 음표 번호는 이 문서에서 별도 표시가 없으면 자동본의 시간순 1기준이다.

### 3.2 문자 관측 구간과 지속 발음의 끝은 같은 근거가 아니다

[audio/inference.py](../svp_alignment/audio/inference.py)의 `decode_words`는 CTC 경로를 `merge_tokens`로 합친 문자 시각을 반환한다. 그 마지막 문자 시각을 지속 발음의 실제 종료로 확정할 수는 없다. CTC의 짧은 레이블 반응과 blank의 모호성 때문에 음성이 이어지는 전체 길이가 문자 구간에 포함되지 않을 수 있다는 한계가 공식 문서에도 설명돼 있다. [TorchAudio 2.8 설명](https://docs.pytorch.org/audio/2.8/tutorials/ctc_forced_alignment_api_tutorial.html#inconsistent-treatment-of-blank-token)

따라서 실제 발음이 해당 음표까지 이어졌는지 청취하지 않은 상태에서 모든 짧은 구간을 모델 오검출로 단정하지 않는다. 확인된 설계 문제는 **문자 관측의 끝을 연장음 판정의 엄격한 종료 경계로 사용한 것**이다. 더 큰 모델도 같은 의미의 관측값만 주면 이 문제를 자동으로 해결하지 못한다. Qwen의 단어 범위 역시 개별 음절 경계나 지속음의 정답으로 간주하지 않는다.

### 3.3 철자 음절 수와 부분 단어 제거

[alignment/general_lyrics.py](../svp_alignment/alignment/general_lyrics.py)의 `_parts`는 기본적으로 영어 모음군으로 음절 수를 추정한다. 기존 SVP에 같은 원문 단어와 `+`가 있으면 보조 근거로 쓰지만, 입력 대부분이 `la`인 이번 자료에는 그 근거가 부족하다.

- `victory`는 `vic/tor/y` 3부분으로 추정됐다. 26.250초·26.495초의 두 음표에 두 부분만 대응해 단어 전체 배치가 제거됐다. 사용자 수정본은 같은 음표에 `vic`, `tory`를 넣었다.
- `behind`는 2부분으로 추정됐으나 29.640–30.065초의 한 음표만 대응해 전체 배치가 제거됐다. 사용자는 그 음표에 `behind` 전체를 넣었다.
- 첫째·둘째 `Tomorrow`도 각각 3부분 중 2개만 대응해 전체 배치가 제거됐다.

이는 실제 가창의 음절 수를 확정한 결과가 아니다. 한 음절이 여러 음표에 걸치거나 한 음표에 여러 음절을 넣는 표현을 후보로 다뤄야 한다는 근거다. 일부 음절만 남기지 않는 현재 제거 정책은 원문 보존 의도가 있지만, 고정한 음절 수가 틀리거나 압축 배치를 지원하지 않으면 단어 전체 누락을 만든다.

### 3.4 최종 가사 기호의 연결 관계

자동 SVP의 `library[0].notes[82:87]`에는 `society / la / + / la / +`가 기록돼 있고, 해당 음표의 `phonemes`는 빈 문자열이다. 공식 의미에서 `+`는 앞 단어의 다음 음절, `-`는 앞 발음의 지속을 나타낸다. 중간 일반 가사 `la`는 뒤의 `+`가 의도한 단어에 연결되는 것을 방해할 수 있다. [Dreamtonics 공식 설명](https://sv1.docs.dreamtonics.com/en/synthv/basic-usage/pianoroll)

| `+`가 기록된 음표 | 시작 초 | 내부 대응표의 단어 | 앞에서 가장 가까운 일반 가사 |
| ---: | ---: | --- | --- |
| 85 | 51.565 | society | la |
| 87 | 51.965 | society | la |
| 178 | 118.015 | another | la |
| 180 | 118.560 | another | la |
| 191 | 122.600 | away | la |

[verification/general_lyrics.py](../svp_alignment/verification/general_lyrics.py)의 `verify_placement`는 내부 대응표의 인덱스·순서와 예상 필드를 확인한다. 최종 SVP에서 `+`가 실제로 어떤 단어의 음절로 해석되는지는 검사하지 않는다. 위 5곳은 기호 문맥의 위험을 확인한 것이며 실제 합성 발음 오류가 확정된 것은 아니다. Studio 열기·합성·청취는 NOT_RUN이다.

### 3.5 배치 상태와 검토 상태의 혼합

현재 CSV와 작업 이력을 구분해 집계하면 다음과 같다.

| 음표 상태 | 개수 |
| --- | ---: |
| ALIGNED | 121 |
| 배치했으나 검토가 필요한 UNKNOWN | 80 |
| TXT와 대응하지 못해 원문을 유지한 UNKNOWN | 55 |
| 합계 | 256 |

미대응 55개는 `la` 47개와 기존 `-` 8개다. 배치한 UNKNOWN 80개 중 3개는 기존 `-`와 결과 문자열이 같아도 실제로 `boy` 지속음에 다시 대응됐다. 따라서 문자열이 같거나 `la`라는 이유만으로 미처리라고 판정할 수 없다. TXT에 실제 `la`가 있는 곡도 고려해야 한다.

`verify_placement`는 미배치 단어를 제외한 목록과 복원 결과를 비교한다. 이때의 순서 PASS는 배치된 부분의 기록 일치이며 TXT 전체 배치 성공을 뜻하지 않는다. 현재 미배치는 10단어다. [manager.py](../svp_alignment/jobs/manager.py)는 이를 기록하고도 REVIEW_READY로 진행하며, 저장 완료 후 COMPLETED가 된다.

[presentation.py](../svp_alignment/ui/presentation.py)는 이미 UNKNOWN·미배치·NOT_VERIFIED를 표시한다. 경고가 전혀 없는 문제가 아니라, 미대응·근거가 약한 배치·지속음 후보를 같은 UNKNOWN으로 묶고 파일 저장 성공과 가사 입력 완성을 구분하는 흐름이 부족한 문제다.

### 3.6 마지막 단어와 음표 영역의 불일치

마지막 TXT 토큰 `run`은 `word_index=177`, 24행 44열이며 모델 구간은 204.3325–204.5125초다. 보컬 음표는 145.32초에 끝난다. 모델이 마지막 반복을 잘못 정렬했는지, TXT·WAV·SVP의 적용 범위가 다른지는 실제 청취·입력 대조로 확인해야 한다. 단어를 145초 안으로 강제 이동시키거나 관측값을 잘라서 배치율을 높이지 않는다. 이 불일치는 지속음 임계값과 별도 검토 대상이다.

## 4. 임계값 변경 실험

새 모델 추론 없이 같은 원본 음표·TXT·저장 관측·일대일 배치를 사용하고, 지속음 조건만 메모리에서 바꿨다. 이전 비교 시점의 사용자 수정본을 기준으로 UUID가 공통인 251음표를 평가했으며 삭제된 5음표는 제외했다. 실제 음성 정답률이 아니라 사용자의 가사 교정과의 일치 비교다.

| 변경 조건 | `la → -` 29곳 중 복구 | 기존 결과에 없던 `-`가 수동본과 다른 곳 | 미배치 단어 |
| --- | ---: | ---: | ---: |
| 현재 70%, 종료 +0.08초 | 0 | 0 | 10 |
| 겹침만 50%로 완화 | 1 | 0 | 10 |
| 겹침만 0%로 완화 | 1 | 1 | 10 |
| 종료만 +0.5초로 완화 | 0 | 0 | 10 |
| 겹침 50%, 종료 +0.5초 | 7 | 0 | 10 |
| 겹침 0%, 종료 +1.0초 | 28 | 9 | 10 |
| 앞 배치 음표 이후 미매칭 음표를 모두 `-`로 처리 | 29 | 14 | 10 |

강하게 완화하면 `vic`, `tory`, `behind`, 다음 음절 `+`, 사용자가 `la`로 남긴 자리까지 연장음으로 처리한다. 이 결과는 임계값 하나를 바꾸거나 잔여 `la`를 일괄 치환하는 방법으로 가사 배치 문제를 해결할 수 없음을 보여 준다. 마지막 행은 현 배치 이후의 빈 음표를 채우는 실험이며 모든 일반 가사를 무조건 치환한 실험이 아니다.

## 5. 구현한 가사 배치 계약

### 5.1 단어 구간과 음절·지속음 공동 배치

새 일반 곡 대응은 `placement_policy=word_note_groups_v1`로 식별한다. 원문 토큰의 인덱스·행·열·대소문자·반복을 고정하고 단어 시작 후보를 시간 순서로 찾는다. 각 단어가 소유할 연속된 기존 음표를 정한 뒤, 음표마다 1개 이상 음절을 시작하거나 앞 음절을 지속하는 후보를 함께 비교한다. 이전의 음절 하나·음표 하나 강제와 사후 70% 겹침 조건을 사용하지 않는다.

- 문자 관측이 원문 철자와 정확히 대응할 때 내부 문자 시각을 부드러운 비용으로 사용한다. 문자 시각이 없으면 음표 순서만 후보 근거로 쓰며 개별 음절 시각이나 신뢰도 확률을 만들어 채우지 않는다. Qwen의 단어 범위를 음절 경계로 복제하거나 보간하지 않는다.
- 철자 음절 수는 추정이다. 여러 추정 음절을 한 음표에 압축할 수 있고, 압축된 단어는 TXT의 정확한 부분문자열들로 기록한다. 예를 들어 `victory`의 세 추정 부분이 두 음표에 배치돼도 원문을 복원할 수 있으면 단어 전체를 취소하지 않는다. 실제 분할·발음은 검토 대상으로 남는다.
- 같은 단어의 음표 구간 안에서는 일반 가사·`+` 사이에 출처 없는 `la`를 남기지 않는다. 지속음은 `-`와 앞 발음 시작 음표의 소유자로 기록하고 실제 지속·공백·새 자음은 청취 전 확정하지 않는다.
- 다음 원문 토큰의 시작, 미지원·미배치 토큰, 악보의 공백은 앞 단어가 무제한으로 `-`를 차지하지 못하게 하는 경계다. 문자 관측 종료가 실제 발음 종료라는 가정은 제거하되, 추가 근거가 없는 긴 꼬리·마지막 발음 뒤 음표는 보류한다. 음표 영역 밖 단어를 억지로 옮기거나 관측 시각을 자르지 않는다.
- 서로 가까운 비용의 시작 후보가 남거나 압축·내부 음절·지속음이 추정이면 `NEEDS_REVIEW`다. 후보 비용은 정확도 확률이 아니다. `la` 자체를 특수한 쓰레기 문자열로 취급하지 않으며 TXT에 있는 `la`는 정상 단어로 연결한다.

검색의 수치 경계는 단어 시작과 음표 시작 차이 0.55초 이하, 단어 창과 음표의 간격 0.35초 이하를 사용한다. 선택한 후보 비용과 차이가 0.25 이하인 다른 시작 후보는 검토 대상으로 표시한다. 악보 공백 기준은 `max(0.18, min(0.45, 이전 음표 길이 × 0.6))`초이고, 다음 토큰의 시작이 알려진 경우에만 관측 종료 뒤의 제한된 꼬리를 검토한다. 꼬리 예산은 인접 최대 8음표의 길이 중앙값을 사용한 `max(0.5, min(1.5, 중앙값 × 3))`초다. 이 값들은 검색·보류 정책이며 실제 발음 종료 허용 오차가 아니다.

### 5.2 배치 행동·검토 상태·품질

모든 원본 음표에 다음 행동 중 하나를 기록하고, 모든 TXT 토큰은 배치 또는 사유 있는 미배치로 계수한다.

| 행동 | 소유·직렬화 계약 |
| --- | --- |
| `WORD_START` | 원문 단어의 첫 발음 시작. 단어 또는 압축된 첫 원문 조각을 기록하고 소유자는 자신 |
| `NEXT_SYLLABLE` | 같은 원문 단어의 다음 음절 `+`. 소유자는 해당 단어의 첫 시작 음표 |
| `CONTINUE` | `-`로 직전 발음 시작 음표의 마지막 음절을 지속. 다음 단어를 대신하지 않음 |
| `TEXT_FRAGMENT` | 압축된 단어의 후속 원문 조각. 원문의 정확한 문자 시작·끝 위치와 문자열을 기록 |
| `UNASSIGNED_ORIGINAL` | 미대응 원문 유지. 단어·음절 소유자 없이 원래 가사와 사유를 보관 |

각 행동은 원문 토큰, 음절 인덱스, 소유 음표, 원문 부분문자열 범위, `AUTO_CANDIDATE`·`NEEDS_REVIEW`·`USER_CONFIRMED` 중 검토 상태를 가진다. 배치 행동과 기존 UNKNOWN 표시는 독립적이다. 원래 `-`와 문자열이 같아도 새로 대응한 지속음일 수 있고, 원래 `la`와 같아도 실제 원문 단어로 배치됐을 수 있다.

음표 비교 CSV의 기존 열을 유지하고 `placement_action`, `review_status`, `word_index`, `syllable_ids`, 1기준 `owner_note_number`, `placement_policy`, `symbol_risk`를 추가했다. 가사 CSV에는 단어별 배치·검토 상태와 정책·기호 위험을 추가하며 지속음을 포함한 전체 소유 음표 구간을 표시한다.

`summarize_quality`는 미대응 음표, **배치했으나 검토가 필요한 음표**, 사용자 확인 음표와 기호 위험을 따로 센다. 미대응과 배치 후 검토 수는 중복 합산하지 않는다. 미대응·미배치 단어·기호 위험이 없으면 자동 배치 완료 후보이며, 청취·합성 확인 완료를 뜻하지 않는다. 이전 기록의 세부 소유 정보를 복원할 수 없으면 `quality_known=false`, 세부 수치와 배치 완료 여부는 미상이다. CSV 복원 시 정확한 `True`·`False` 문자열만 불리언으로 해석한다.

### 5.3 최종 SVP 검증과 초안 교정

`verify_placement`는 새 정책에서 전체 원문 계수·순서·반복, 음절의 단 한 번 소비, 연속 단어 구간, 원문 조각 전체 복원, 행동과 필드 일치, 최종 `+`·`-` 소유자를 검사한다. 미대응 일반 가사가 체인을 가로막거나 다른 단어의 발음에 연결되면 검증 오류로 중단한다. 저장·재파싱·게시 경계에서는 `lyrics` 외 JSON 전체 동일성도 다시 검사한다. 기호 체인 검사는 구조적 연결의 검증이며 Studio 발음 검증을 대신하지 않는다.

GUI는 미대응 원문 유지·미배치 단어·배치 후 검토·사용자 확인·기호 위험 등을 따로 필터링한다. 비교표는 읽기 전용이고, 행을 선택하면 원문 위치·원본 WAV 구간과 별도 교정기를 연결한다. 새 일반 곡의 REVIEW_READY 초안에서 단어 시작·다음 음절·지속음과 확인 상태를 교정할 수 있다. 수정은 원문 단어·음절 순서, 연속 음표 구간과 다른 단어의 소유 범위를 검증하고 공용 기호 직렬화기를 거친다. 음표를 추가·삭제하거나 시간·음높이를 편집하지 않는다.

교정마다 새 `draft_revision`을 만들고 이전 초안은 불변으로 보존한다. `review-context.json`의 해시, 입력·관측 해시, 화면이 본 정확한 초안 버전을 확인한다. 중복·오래된 적용, 실패·취소·완료 작업의 교정은 거부한다. 초안 기록을 검증해 복원하므로 교정·내보내기 때 모델을 다시 실행하지 않는다. 미완성 결과도 부분 초안으로 저장할 수 있으나 가사 배치 완료로 승격하지 않는다.

### 5.4 이전 작업·Counting Stars 호환과 남은 한계

- 기존 COMPLETED의 파일·해시·보고서는 그대로 복원하고 다운로드·미리듣기를 유지한다. 새 확인 상태를 소급하지 않으며 완료 파일을 교정하지 않는다.
- 이전 일반 곡의 미완료 초안에 현재 정책·검토 문맥이 없으면 재검사가 필요하다. 이전 대응 자료를 새 정책처럼 읽어 교정·내보내기하지 않는다.
- **Counting Stars 기존 분석 자료** GUI 옵션은 기존 캐시 대응을 그대로 유지한다. 새 품질은 미상이고 새 교정기는 비활성이다. 현재 일반 곡의 새 모델 경로를 선택하면 새 정책으로 분석할 수 있다. 기존 타이밍 CLI의 API·결과 바이트·실패 계약은 유지한다.
- 발음 사전·실제 유성음 종료·새 자음 검출·자동 번역을 추가하지 않았다. 지속음과 압축 후보의 실제 발음은 Studio 열기·합성·청취 검증이 필요하다. 마지막 204초 `run`과 145초 음표 끝의 불일치도 자동으로 정답을 선택하지 않고 미배치 검토 대상으로 남긴다.
